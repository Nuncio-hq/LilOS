What LilOS is

CompanyOS: AI-agent employees. Hire them, hand them threads, watch them work in a real folder, step in only when they need you. Each thread is one engine session on one protocol (Hermes first, never glued in). Engine owns sessions, memory, skills, profiles; LilOS owns only its records: company, projects, channels, messages, tickets, employees. Runs on Mac (Electron, two background services), iPhone (paired over Tailscale).

Stage: prototype. prototype/ is UI source of truth: UI change lands in packages/ui (ui-native for mobile) first, Oscar accepts it, then real app implements it. Mock data is not a contract.

Oscar is the client, not a reviewer. He doesn't write code, rarely reads diffs; he accepts or rejects product he can try. You own correctness end to end. "Done": he can try it, with evidence, without reading code. Plain product language. He chats in Vietnamese; repo is English.

How work happens

GitHub issues are source of truth

  • Nuncio-hq/LilOS via gh. feature is parent issue with product outcome; sub-issues are vertical slices.
  • Modules: every open issue is one module's sub-issue; its board card carries that Module field. Each slot: swap or empty it, rest still works: Core (#756: company, projects, threads, agents, tickets, Needs you, lilos_* tools) · Runtimes (#757: Hermes now, others via ACP; models per agent) · Connectors (#758: outside services via CLI or MCP, zero or many) · Mac tools (#759: browser, terminal, Workbench, checkpoints) · Quality (#760: speed, flaky tests, refactors, a11y, iOS upkeep).
  • Labels, only these: agent-ready (criteria + verify plan; anyone may take it; blocked slice gets it when its blocker merges), later (parked), needs-human (waiting on Oscar).
  • Pick open agent-ready slices with no PR (label:agent-ready -linked:pr); finish feature's slices before another.
  • Take it: remove agent-ready, assign yourself, open draft PR with Closes #N early; mark it ready when tier's checks pass (E2E only on ready PRs). One slice at a time; stuck → needs-human. One Status comment (Now / Next / Blocked), edited in place. git commit -s.
  • Done: merged PR closes slice; last slice closes feature. Then check "LilOS" board card is Done; if not, move it (gh project item-edit).
  • Work outside slice → new issue; don't widen PR.

Every feature ships its agent tools

  • Agents must use whatever Oscar can: feature is done only when they can too. Feature issues have Agent tools section; PRs show one real agent call per new tool.
  • Tools, once in packages/contracts/src/harness/tools.ts as <area>_<action> (seen as lilos_thread_read). New AppMethod or user-visible action adds its tool or NOT_AGENT_FACING reason (packages/contracts/src/harness/coverage.ts); test enforces it.
  • Changing company is approval tool (D-#341). Scope comes from session, never agent-passed id. Agents use LilOS surfaces, not engine's browser.

Docs, decisions

  • The code is the documentation. Why is a comment at the rule; this page keeps one line per decision pointing there. Change behavior, update that comment in same PR.
  • Two documents: AGENTS.md (short, auto-loaded; CLAUDE.md links to it), this page. Other Markdown only where tool needs it: README, CONTRIBUTING, SECURITY, issue templates, LICENSE, notices, skills. Plans, logs, research go in issues, PRs. packages/contracts/test/docs.test.ts enforces this.
  • A decision needs an issue and a merged PR. Chat, brainstorm or old doc, without both, was never implemented: open issue, don't build on it. Record only what later agent could undo by accident: architecture, protocol, data ownership, stack.
  • Format: one <li id="d-N"> (another for same issue: d-N-2): rule, Not: what was rejected, refs, file(s) whose D-#N comment holds detail. Add it in that PR. Supersede by rewriting in place; old choice becomes Not: … (was #old). Delete decision no longer in force, its tags.

App Review notes (TestFlight beta)

Paste into App Store Connect when a build goes to review; the demo it describes lives in apps/mobile/src/demo.

What the app is. LilOS is the phone companion for LilOS on the Mac: a Slack-style app where the "employees" are AI agents that run on the user's own Mac. The iPhone app is a client of that Mac — it pairs to the Mac app over a QR code and then works against it (read threads, steer agents, approve or deny their tool calls, watch background jobs).

How to review it — no Mac, no account required. Launch the app → Welcome screen → tap "Try the demo" (under "Connect your Mac"). You are inside a scripted, fully offline demo company where every screen works: threads stream replies, approvals can be allowed or denied, plans, subagents, background jobs, settings. A Demo badge floats on every screen; to leave, Settings → Exit demo (or Connect your Mac for the real pairing flow). Exiting leaves nothing on the device. The demo never opens a network connection, so it also works in Airplane Mode.

Privacy: nuncio-hq.github.io/lilos-site/privacy/

What to Test: LilOS is the phone client for AI employees running on your Mac. Tap "Try the demo" to explore every screen offline — no account or Mac needed.
